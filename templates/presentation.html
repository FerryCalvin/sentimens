Sistem Klasifikasi Sentimen Teks Media Sosial Menggunakan IndoBERT dengan Strategi Multi-Domain

Slide 2 • Latar Belakang

Pemicu Penelitian & Tantangan Linguistik

Perkembangan teknologi digital melahirkan 185,3 juta pengguna internet di Indonesia (penetrasi 66,5% populasi) dengan 139 juta pengguna aktif media sosial (Slice, 2024; DataReportal, 2024). Lonjakan opini publik ini memiliki high volume dan high variety.

Teks opini publik di media sosial didominasi oleh bahasa informal, slang, singkatan, serta campur kode (code-mixing) antar bahasa daerah. Hal ini merupakan tantangan berat bagi model klasifikasi sentimen konvensional seperti Naive Bayes dan SVM yang bertumpu pada representasi Bag-of-Words atau TF-IDF karena mengabaikan urutan kata, relasi antarkalimat, dan negasi (contoh: "tidak buruk" diartikan negatif akibat bias kata "buruk").

Masalah Domain Shift / Dataset Shift (Pan & Yang, 2010): Model yang hanya dilatih pada skenario single-domain cenderung overfitting dan performanya anjlok ketika dihadapkan pada dinamika multi-domain percakapan media sosial yang tidak dapat diprediksi.

Slide 4 • Metodologi

Alur Kerja Penelitian

Penelitian eksperimental ini dirancang secara sistematis dengan tahapan prosedural yang terukur:

  1. Pengumpulan Dataset: Akuisisi data latih multi-domain dan setup data uji kualitatif live.
  2. Penyelarasan Label (Relabeling): Menyatukan label dari berbagai format (teks, skala numerik 0-2, bintang 1-5) menjadi skema numerik terpadu (0 = Negatif, 1 = Netral, 2 = Positif).
  3. Validasi Pakar (Linguist Validation): Validasi acak 200 sampel oleh pakar bahasa FIB Universitas Airlangga guna meminimalkan bias subjektif sistem pada kasus batas (borderline cases).
  4. Text Preprocessing: Pembersihan noise teks tanpa menghapus kata-kata penentu negasi (justifikasi peniadaan stopword removal).
  5. Fine-Tuning Model: Melatih model IndoBERT Base menggunakan GPU Tesla T4 dan menangani class imbalance melalui bobot penalti dinamis.
  6. Integrasi & Evaluasi: Implementasi sistem arsitektur microservices Flask & FastAPI dan evaluasi performa.
Slide 5 • Data & Validasi

Komposisi Dataset & Validasi Pakar

Dataset gabungan berjumlah 21.762 baris dikonstruksi dari 4 rumpun bahasa yang saling melengkapi:

  • IndoNLU (SmSA): 12.760 baris data (domain formal dan semi-formal).
  • NusaX (Jawa + Sunda): 2.000 baris data (melatih model menangani fenomena code-mixing daerah).
  • Ulasan Spotify (Kaggle): 4.002 baris data setelah random stratified sampling (campuran informal & slang).
  • Berita CNBC Indonesia (Kaggle): 3.000 baris data (register jurnalistik, faktual, netral-dominan).

Validasi Pakar: Bapak Nuri Hermawan, S.Hum., M.Hum. meninjau 200 sampel acak secara blind review. Pakar merevisi 8 label (4%) yang didominasi kasus batas (teks saran/permintaan yang dideteksi negatif oleh aturan pemetaan sederhana namun secara pragmatik bernada netral).

Evaluasi ini menghasilkan skor Cohen's Kappa κ = 0,9373 (Almost Perfect Agreement). Penambahan data CNBC menyeimbangkan data dengan meningkatkan proporsi kelas Netral dari 11,6% menjadi 23,88%.

Slide 6 • Praproses

Praproses & Pembagian Dataset

Alur Regex Preprocessing:
  1. Case folding: str.lower()
  2. URL: re.sub(r'http\S+|www\S+', '', text)
  3. Mention: re.sub(r'@[A-Za-z0-9_]+', '', text)
  4. Hashtag: re.sub(r'#\w+', '', text)
  5. Non-Alfabet: re.sub(r'[^a-z\s]', ' ', text)
  6. Normalisasi spasi: re.sub(r'\s+', ' ', text).strip()

Mekanisme Stopword Removal ditiadakan karena kata-kata fungsi negasi (seperti "tidak", "bukan", "belum") sangat krusial bagi mekanisme self-attention model IndoBERT dalam menangani negasi dan sarkasme.

Data final yang bersih dibagi secara Stratified Split menjadi: 15.201 baris Data Latih (70%), 4.340 baris Data Validasi (20%), dan 2.173 baris Data Uji (10%).

Slide 7 • Pelatihan Model

Pelatihan Model & Penanganan Imbalance

Pelatihan model di Google Colab GPU Tesla T4 menggunakan optimizer AdamW, mixed precision (fp16), Learning Rate 2e-5, Batch Size 16, dan sequence length 128 token selama 3 Epoch (total 2.853 training steps).

Weighted Cross-Entropy Loss: Mengingat ketimpangan sisa antar kelas (Positif dominan), diterapkan pembobotan kelas dinamis invers proporsional terhadap frekuensi data latih. Bobot penalti: Negatif 0,9615, Netral 1,3982, dan Positif 0,8034.

Model terbaik secara otomatis dipilih dari Epoch 2 (Val F1-Macro 92,30%, Train Loss 0,1426, Val Loss 0,2706). Memasuki Epoch 3, Train Loss turun ke 0,0728 tetapi Val Loss naik ke 0,3664, menunjukkan munculnya gejala awal mild overfitting.

Slide 8 • Hasil Kuantitatif

Hasil Evaluasi Model pada Data Uji

Pengujian kuantitatif (Offline Evaluation) menggunakan hold-out test set terpisah (N=2.173) menghasilkan skor: Akurasi Global 91,62%, F1-Score Makro 91,24%, Precision Makro 91,10%, dan Recall Makro 91,41%.

Analisis Kinerja per Kelas:

  • Positif (2): F1-Score 93,69% (Precision 93,58%, Recall 93,79%). Performa tertinggi didukung representasi data terbesar dan struktur bahasa positif yang mudah dideteksi.
  • Negatif (0): F1-Score 90,88% (Precision 92,32%, Recall 89,49%). Tingginya recall negatif sangat krusial dalam konteks pemantauan krisis/isu publik.
  • Netral (1): F1-Score 89,14% (Precision 87,41%, Recall 90,94%). Melonjak +15,36 poin dibanding model awal pra-CNBC (73,78%), membuktikan keampuhan domain adaptation.
Slide 9 • Analisis Prediksi

Analisis Kesalahan (Error Analysis)

Berdasarkan sebaran confusion matrix pada data uji (N=2.173):

  • Model mengklasifikasikan dengan benar 673 dari 752 data Negatif dan 846 dari 902 data Positif.
  • Kesalahan terbesar terjadi pada persinggungan kelas Negatif dan Netral: 41 data Negatif salah dideteksi sebagai Netral, dan 27 data Netral salah dideteksi sebagai Negatif.
  • Secara linguistik, pola ini konsisten dengan tipisnya batas demarkasi semantik antara keluhan implisit (yang dikategorikan netral/informasi oleh pakar bahasa) dengan ungkapan sentimen negatif secara eksplisit di media sosial.
Slide 10 • Arsitektur Web

Implementasi Arsitektur Dual-Service

Sistem diintegrasikan menggunakan arsitektur Two-Service Microservices berbasis Python untuk memisahkan tanggung jawab (Separation of Concerns):

  • Layanan Utama (Flask - Port 5000): Merender antarmuka pengguna (Single Page Application), mengelola route REST API, dan memuat model IndoBERT ke RAM secara persisten (Persistent Model Loading) untuk menghindari overhead pemuatan file model 500MB di setiap request.
  • Layanan Scraper (FastAPI - Port 8000): Menjalankan Playwright dalam event loop asinkron murni untuk penarikan data paralel tanpa memblokir thread pelayanan web utama Flask. Komunikasi antar layanan menggunakan client HTTPX.
  • Alur Kerja Asinkron: Pengguna memasukkan kata kunci → Job ID dibuat (status: queued) → respons instan (<1 detik) → Playwright scraping + preprocessing + inferensi model berjalan asinkron di latar belakang (FastAPI & Flask) → klien melakukan polling AJAX per 2 detik → dashboard otomatis merender hasil visualisasi setelah status completed.
Slide 11 • Pengujian

Pengujian Fungsional (Black Box)

Verifikasi fungsionalitas sistem diuji secara menyeluruh menggunakan metode Black Box Testing pada lingkungan localhost.

Pengujian didasarkan pada target PRD yang meliputi:

  • Analisis Teks Tunggal: TC-A01 s.d TC-A03 sukses mendeteksi 3 kelas sentimen; TC-A04 sukses memproses slang gaul; TC-A09 sukses melakukan sanitasi XSS (mencegah injeksi tag script).
  • Analisis Batch CSV: TC-B01 s.d TC-B06 sukses memproses upload, menolak format selain CSV, auto-detect kolom teks, dan mengunduh laporan.
  • Live Scraping & Polling: TC-C01 s.d TC-C07 sukses melakukan scraping asinkron, polling AJAX per 2 detik, filter periodik data, dan penanganan error server down.

Lulus Uji 25/25 Test Cases (100% Pass) dengan Zero Failures. Seluruh kriteria kesuksesan (SM-01 s.d SM-08) dan 10 Non-Functional Requirements (NFR) dinyatakan terpenuhi.

Slide 12 & 13 • Akhir

Kesimpulan & Saran

Kesimpulan Utama
  • Model IndoBERT multi-domain mencapai akurasi global 91,62% (melampaui target PRD ≥80% sebesar +11,62 poin) dengan generalization gap sangat kecil (1,03%).
  • Penambahan domain CNBC and dynamic class weighting melipatgandakan performa kelas Netral (+15,36%).
  • Sistem dual-service Flask-FastAPI berhasil diimplementasikan secara asinkron dan lulus uji Black Box 100%.
  • Verifikasi anotasi dataset oleh pakar menunjukkan validitas yang sangat tinggi (kappa = 0,9373).
Saran Penelitian Lanjutan
  • Menerapkan teknik label smoothing (ε = 0,1) untuk mengurangi overconfidence model.
  • Melakukan studi ablasi yang membandingkan performa model IndoBERT Base dengan IndoBERTweet pada dataset multi-domain yang sama.
  • Migrasi in-memory job store ke sistem database persisten (SQLite/Redis) dan Celery untuk skenario multi-user berskala produksi.
  • Mengintegrasikan modul scraper dengan mekanisme rotasi proxy dan cookie refresh terjadwal untuk menghindari bot-detection.
